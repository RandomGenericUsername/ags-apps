- (direction) User chose the coaching path for the REQ-008 architecture run.
- (direction) Program deliverables are per-app repos plus the repo template; each repo uses the mu project's AGENTS/tickets/LIFECYCLE/worktree-guard model. The spine governs shared invariants only, not the whole deliverable set.
- (direction) User rejects restart as a fallback. Exact meaning to pin: either no restart at all on wallpaper change (all apps live) or explicit per-app restart mode with no automatic fallback.
- (decision) Restart is an explicit per-app manifest mode, not an automatic fallback. It is allowed when the app can justify it (for example the bar) and remains properly interfaced. If investigation later shows live refresh is worthwhile for that app, moving it to live is a future iteration, not a contract change.
- (decision) The spine audience is both: app builders/agents and the runtime/provisioning maintainers. The spine must be self-contained on shared invariants; app-specific detail stays in each app repo's AGENTS/tickets.
- (decision) mode: restart means the app asserts it is safe to restart at any moment, including while visible or mid-operation, without losing anything the user cares about. If that is not true, the app must be mode: live. unsavedState is a hard flag for editors; mode: restart is a stronger all-times safety assertion. Capture's final mode is decided in REQ-011; if it cannot prove all-times safe restart it must be live, unless a separate idle-restart handshake is explicitly designed.
- (decision) capture-tool is mode: live. Restart cannot guarantee all-times safety while a capture or settings surface is in use, so it is not a restart app.
- (decision) No legacy path and no compatibility shim. The runtime is the only palette-refresh trigger and invokes each running live app after the palette repoint. An app without a manifest is not refreshed; it goes stale until migrated. The whole machine migrates in this program, so no extra effort is spent on a transitional restart path.
- (decision) Manifest lives at the app repo root as app.manifest.json and is deployed into the app config dir; the runtime reads it from there. No central app registry.
- (decision) palette-refresh returns JSON: {"ok":true} on success or {"ok":false,"error":"..."} on failure. The runtime treats malformed/empty output, non-zero exit or timeout as failure.
- (decision) Live-refresh failures are reported through the existing reload_failures result and the notification card. No retry and no restart fallback. The app stays running and may be stale until the next successful refresh.
- (decision) Live app refreshes run in parallel because the apps are independent. Each app gets a 5s timeout, its own structured log record (instance, configDir, palette hash, start/end, duration, argv, exit code, JSON response, error) and one failure does not stop the others. The final summary is ordered by discovery order, not completion order, for traceability.
- (decision) Restart-mode apps run in a serialized lane: confirmed quit, no concurrent ags run, no exit-0 misclassification. Only one restart app remains (bar). The restart lane may run alongside the parallel live lane because live requests do not bundle; wallpaper.state done is published after both lanes settle.
- (decision) Final install layout: <install>/apps/<app>/<tag>/ for every app; config/ags -> bar, config/ags-* -> the other apps; shared platform shortcut at <install>/apps/node_modules/ags-platform. The old config/node_modules shortcut is not an ancestor of the per-app checkouts and must move.
- (decision) dotfiles-v3 owns the per-app pin list (repo, tag, config link, optional bin link, bar palette pointer). dotfiles-provision provides one generic role loop consuming that list; verify and deploy-coverage consume the same data.
- (decision) The pilot app repo is the repository template. ags-apps is only the temporary migration workshop; when the last app moves it is archived, not kept as a meta repo.
- (decision) Cutover invariant: exactly one owner per app at every commit. Add the app to the dotfiles-v3 list, add it to the old ags_apps role exclusion list, remove its old link, verify no duplicate, then delete the old role/pin when the last app moves. This is deployment cutover, not a runtime fallback.
- (direction) Consumer-side work must be tracked in each corresponding repo's own dev flow: dotfiles-v3, dotfiles-provision, dotfiles-runtime, ags-platform, contracts. The ags-apps epic links to those tickets; it does not swallow them.
- (decision) App repo names are ags-bar, ags-notifications, ags-capture-tool, ags-clipboard, ags-wallpaper-selector, ags-icme, ags-btop-theme-studio. Each repo root is the app package (app.tsx at root); no source subdir.
- (decision) Full clipboard rename: repo ags-clipboard; config dir ags-clipboard; AGS instance clipboard; window clipboard-window; launcher clipboard-ui; keybind description Open clipboard history. The dotfiles-runtime clipboard daemon keeps its name. hypr-pano names are retired.
- (decision) Apps apply the current palette at startup; the runtime only calls palette-refresh on a palette change while they run. Missing or invalid manifest: runtime does nothing to that app and logs a structured error; app-repo CI validates the manifest before deploy. No legacy path.
- (decision) The runtime does not declare the app list. It discovers running apps and reads each app.manifest.json; the app declares live/restart. dotfiles-v3's list is provisioning data (what is installed), not runtime refresh policy.
- (decision) This program supersedes the 2026-10-16 deferral in GUIDE-ags-app-repos-refinement.md and the parent spine Deferred item. The pilot (ags-clipboard) is the harness/install exit-gate proof; the per-app split is now the decision of record.
- (event) Spine finalized after reviewer gate PASS (adversarial r4); lint clean. EPIC-002/REQ tickets aligned; next step is per-repo consumer tickets and REQ-009 pilot.
